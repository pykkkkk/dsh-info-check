# 手动回归清单

**适用版本：** dsh-info-check 0.2.0  
**验证环境：** DSH 0.2.2-rc.3 Desktop（Web GUI）  
**目标：** 在不依赖浏览器自动化的情况下，用固定步骤覆盖用户可见的关键路径。  
**原则：** 每项都记录 **Pass / Fail / Blocked**，并附证据（截图、Console、台账行号）。

## 前置条件

1. 硬刷新 Web GUI（Ctrl+Shift+R）。
2. 确认标题旁的下划线“需求核对”存在，且开关处于开启状态。
3. 新开一个测试会话，使用只读任务，例如：

   ```text
   测试任务：只读检查 README.md 的前 10 行，告诉我标题和许可证，不要修改文件。
   ```

4. 设置页中临时使用以下值，验证后恢复：

   | 设置 | 建议值 |
   |---|---|
   | 里程碑数量 | 3 |
   | 期望程度 | 较好 |
   | 自动计时 | 30 秒 |
   | 细节问题数量 | 3 |
   | 新对话默认开启 | 开 |
   | 台账 | 开 |

5. 打开 `.dsh-info-check/ledger.md`，记录测试开始前的行数。

## 1. 设置页

| 步骤 | 预期 |
|---|---|
| 点击标题旁带下划线的“需求核对” | 设置页打开，标题旁开关仍在 |
| 检查字段 | 当前对话、里程碑数量、期望程度、自动计时、细节数量、新对话默认、台账开关/路径都在 |
| 把自动计时改为 25，保存，关闭再打开 | 值保持 25 |
| 改回 30，保存 | 值保持 30 |
| 拖动设置页右边缘 | 可调宽；最大不超过当前高度；双击复位 |
| 点关闭 | 设置页关闭，开关仍在 |

## 2. 会话开关

| 步骤 | 预期 |
|---|---|
| 关闭当前会话开关 | 开关变为关闭；工具列表下一步不再出现 `info_check` 等工具 |
| 重新打开 | 工具恢复；已在流程中的待确认卡按插件规则处理 |
| 打开另一个会话 | 当前会话的关闭状态不应影响另一个会话 |

> 不要在验收流程进行中关闭开关；先结束当前卡，再测试开关。

## 3. 需求核对闸门

| 步骤 | 预期 |
|---|---|
| 发送测试任务，等待 `info_check` | 第一张卡为“dsh-info-check · 需求核对” |
| 检查章节 | 我的理解、完成标准、范围外、里程碑各自显示 |
| 检查要点布局 | 每点一个独立文本框；序号在左侧独立序号框；文本里不带序号 |
| 增加一个要点 | 新点出现，序号自动顺延 |
| 删除一个要点 | 点消失，后续序号自动前移 |
| 末尾备注栏写“回归-需求备注” | 文本保留，不参与编号 |
| 拖动右边缘、双击复位 | 调宽生效；最大不超过高度；双击恢复 |
| 勾选确认并继续 | 备注进入 `edited_brief` 的“补充备注”，台账可查 |
| 进入细节步骤 | 细节问题数量与设置一致；上限 > 1 时至少 2 条，最多按设置 |

## 4. 方案确认闸门

| 步骤 | 预期 |
|---|---|
| 方案卡出现 | 顶部标注“dsh-info-check · 里程碑确认” |
| 检查布局 | 方案、影响范围每点独立文本框 + 左侧序号框 |
| 改一条要点，加一条要点 | 返回的 `edited_plan` 保留修改和新增点 |
| 末尾备注写“回归-方案备注” | 进入 `edited_plan` 的补充备注 |
| 点“停止计时” | 倒计时冻结，卡片不关闭 |
| 再点“按此方案执行” | 流程继续，不重复弹方案卡 |

## 5. 里程碑验收闸门

| 步骤 | 预期 |
|---|---|
| 里程碑完成，发验收卡 | 只读布局；每点“序号框 + 内容框” |
| 检查内容 | 完成内容、验证证据、未完成/风险分别显示 |
| 末尾备注写“回归-验收备注” | 备注通过 `notes` 返回，并写入台账 |
| 停止计时 | 倒计时冻结，卡片保留 |
| 点“验收通过” | 返回 `accepted`，进入下一里程碑 |

## 6. 返工分支

| 步骤 | 预期 |
|---|---|
| 在验收卡点“需要返工” | 打开“返修说明”浮窗 |
| 不填理由直接提交 | 提示理由必填，不关闭流程 |
| 填“回归测试：补充一条验证证据”并提交 | 返回 `rework`，`feedback` 为该理由 |
| Agent 按理由补充证据，再次发验收 | 新验收卡出现；台账同时记录返工和再次验收 |
| 再次点“验收通过” | 返回 `accepted`；不得跳过返工直接进入下一里程碑 |

## 7. 交付确认闸门

| 步骤 | 预期 |
|---|---|
| 准备最终结果前，发交付卡 | 只读布局；完成程度、交付内容、未完成/限制、验证分别显示 |
| 末尾备注写“回归-交付备注” | 备注通过 `notes` 返回并写入台账 |
| 停止计时 | 倒计时冻结，卡片保留 |
| 点“确认交付” | 返回 `confirmed`，允许输出最终结果 |

## 8. 调整分支

| 步骤 | 预期 |
|---|---|
| 在交付卡点“需要调整” | 打开“调整说明”浮窗 |
| 不填理由直接提交 | 提示理由必填 |
| 填“回归测试：检查调整说明”并提交 | 返回 `adjust`，`feedback` 为该理由 |
| Agent 按理由处理后重新发交付卡 | 备注/理由进入台账；再次确认成功 |

## 9. 台账

| 检查 | 预期 |
|---|---|
| 需求核对记录 | 包含用户确认版、细节回答、需求备注 |
| 方案确认记录 | 包含用户确认方案、增删点、备注 |
| 验收记录 | 包含完成内容、证据、风险、用户决定和备注 |
| 返工记录 | 包含 `需要返工`、反馈理由、再次验收 |
| 交付记录 | 包含完成程度、交付内容、限制、验证、备注 |
| 调整记录 | 包含 `需要调整`、反馈理由、再次确认 |
| 手工修改 | 不允许；只读检查即可 |

## 10. 浮窗通用检查

| 检查 | 预期 |
|---|---|
| 最大高度 | 不超过视口 75% |
| 最大宽度 | 不超过当前浮窗高度，也不超过视口 75% |
| 右边缘手柄 | 可见、可拖动；拖动中不选中文本 |
| 双击手柄 | 恢复默认宽度 |
| 内容滚动 | 点多时内部滚动，不撑破卡片 |
| 关闭卡片 | 不留下悬挂的确认状态 |
| 备注为空 | 不显示 `undefined` 或空备注行 |

## 失败时

1. 截图浮窗整体和右侧边缘手柄。
2. 打开 DevTools Console，保存报错。
3. 记录对应卡片、操作步骤、预期/实际。
4. 不要手工编辑 `.dsh-info-check/ledger.md`；保留现场。
5. 修复后从失败项开始重跑，不要求整轮重来。
