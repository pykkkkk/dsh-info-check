# dsh-info-check

开工前核对意图，按里程碑确认方案，完成后验收，交付前确认完成程度，并把每次选择写进工作区台账。

## 它做什么

1. **意图核对（`info_check`）**：agent 在动手前先复述目标，并给出可检查的完成标准、范围外、1–3 个里程碑。核对在**对话正中央的浮窗**里出现（半透明遮罩 + 圆角卡片），顶部标注 **dsh-info-check**；第一页是**按小标题拆开的可编辑文本框**（我的理解 / 完成标准 / 范围外 / 里程碑），用户可以直接在对应标题下改、加、删，勾选“我已确认”后进入细节选择（2–3 道单选/多选）。确认后 agent 才开始执行；用户改过的版本会作为 `edited_brief` 返回给 agent，并以它为准。
2. **里程碑确认（`confirm_milestone`）**：需求核对之后**只调用一次**，确认整体执行方案/第一个里程碑（做什么、改哪些文件、怎么验证）；后续里程碑不再调用它。它和需求核对使用同一套浮窗结构：顶部 **dsh-info-check** 徽标 + “里程碑确认”，方案按 `方案` / `影响范围` 小标题拆成独立文本框；勾选“我已确认以上方案”后按此执行。倒计时条右侧有 **“停止计时”**：点击后倒计时停止、浮窗保留，用户可以慢慢修改，改完再按“按此方案执行”。如果 60 秒内没有任何操作，会自动跳过并继续执行。用户改过的方案会作为 `edited_plan` 返回给 agent，并以它为准。
3. **里程碑验收（`accept_milestone`）**：每个里程碑完成后，agent 提交完成内容、验证证据和未完成/风险；浮窗顶部标注 **dsh-info-check · 里程碑验收**，**报告是只读的**（不需要用户改），带倒计时和“停止计时”。用户点“验收通过”进入下一个里程碑；点“需要返工”会打开 **“返修说明”浮窗**，用户填写不通过的理由，理由作为 `feedback` 返回给模型，模型据此修改后再次验收。
4. **交付确认（`confirm_delivery`）**：在呈现最终结果前，agent 提交完成程度、交付内容、未完成/限制和验证；浮窗顶部标注 **dsh-info-check · 交付确认**，报告同样是只读的。用户点“确认并交付”后才输出最终结果；点“需要调整”会打开 **“调整说明”浮窗**，理由作为 `feedback` 返回，模型修改后再确认交付。
5. **工作区台账**：每次核对、里程碑确认、里程碑验收和交付确认都会追加到 `.dsh-info-check/ledger.md`，包含目标、回答、方案、完成情况、决定和时间，方便复核“用户选了什么、agent 怎么执行”。

## 开关

“创造模式”旁边有一个“需求核对”开关（新会话行在创造模式控件右侧；进入会话后在标题旁的 `创造模式` 标签右侧）：

- 每个对话**独立**：一个对话关闭不会影响其他对话。
- 默认开启；关闭只影响当前对话，策略段不再注入，`info_check` / `confirm_milestone` 也从该对话的工具列表消失。
- 开关通过当前对话的 `/dsh-info-check on|off` 命令记录，状态由会话日志投影；fork/resume 会沿用历史选择。
- 点“需求核对”四个字会打开插件的**设置浮窗**（同样是对话正中央的圆角浮窗）；设置项暂未实现，先展示占位内容和当前对话状态。

## 使用方式

直接提任务即可。对非平凡任务，agent 应先调用 `info_check`；确认后每进入一个里程碑，会调用 `confirm_milestone`。两张卡都是“可编辑的文本 + 勾选确认 + 明确的主按钮”，区别只是需求核对多一步细节选择。简单任务（单文件小改、规格已经完整）可以直接做。

## 视觉与动效

- 形式：对话正中央的浮窗（半透明遮罩 + 自适应卡片，14px 圆角；宽度最大 75vw、高度最大 75vh）。
- 结构：灰色 `dsh-info-check` 徽标 → 标题 + 细线步骤条 → 说明 → 按小标题拆开的独立文本框（15px 纯黑标题 + 13px 正文）→ 底部勾选与操作；不再有卡片套卡片。
- 尺寸：内容短时窗口自动收短，内容长时在 75vh 内滚动；左右不超过 75vw，四边都留出空间。
- 配色：按你提供的 `design-style-guide`：DeepSeek Blue `#4D6BFE` 作为唯一强调色，Ink `#1F1F1F`，Slate `#64748B`，页面底 `#F5F6F8`，阅读区 `#FAFBFC`；主色只用于主按钮和选中/勾选态。
- 动效：按钮/选项按压回弹、指针波纹、弹性复选框、步骤条与倒计时条过渡；`prefers-reduced-motion` 下关闭。
- 开关：只有小开关 + **下划线文字**，没有外框/胶囊底；点击文字打开设置浮窗。
- 详细设计说明见 `docs/UI.md`。

## 限制

- 只对**根会话**生效；子代理不能提问，应把未决问题写进最终结果。
- 超时跳过依赖 Web 问题卡的倒计时：卡片获得焦点或用户正在编辑时倒计时会暂停，因此“离开 60 秒”会跳过，“盯着看”不会。
- `confirm_milestone` 的“跳过”是用户显式选择，等同于继续执行该方案；这不是对未确认范围的授权。
- 台账只写在工作区内的 `.dsh-info-check/`；若会话目录不可写，记录会跳过并在日志中提示。
- MVP 未实现“未确认时硬性拦截写工具”；agent 可能不遵守策略。后续可加 `strict` 门（`ctx.tools.guard`）。
- 每个对话的开关是一次 `/dsh-info-check on|off` 命令，因此会在该对话的聊天记录里留下一条命令行；这是换取“可复核、可 fork/resume”的代价。
- 设置浮窗目前只有占位内容，尚未提供实际设置项。
- 浮窗依赖客户端 `react-dom` 的 portal；若某个部署没有该模块，会退化为输入框内的卡片。
